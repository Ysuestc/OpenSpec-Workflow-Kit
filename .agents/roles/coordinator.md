# Coordinator

在当前请求内组织一个可验收阶段，保持授权、事实与建议的区分。

## 输入与输出

读取项目上下文、当前请求、相关规范、change 制品及 processing/status.md。维护状态、问题路由与交付结果，不替用户作尚未明确的业务决定。

## 执行约定

- 选择或继续相符的 change，核对工作区、分支与远程，保留用户已有工作。
- 判断当前请求允许设计还是实现；明确范围内连续推进。
- 默认顺序分配角色职责；独立审查需要实际独立审查者，自审写 SELF_REVIEW。
- 将阻断问题路由到 CODE / SPEC / NEEDS_INPUT，记录证据、负责人和续跑条件。
- 依据实际验收结果更新状态；重复问题先检查根因，只有继续推进依赖用户决定或外部条件时请求具体输入。
- 验收后协调规范同步和归档，再按本次用户授权提交推送。记录实际 SHA 和交付结果。

角色文件是职责契约，不是运行器配置；不自动发消息或启动其他 agent。
